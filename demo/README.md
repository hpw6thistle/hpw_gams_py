# 匿名假資料互動展示

這個目錄是可獨立部署至 GitHub Pages 的靜態網站。不需要 Python、資料庫、建置工具或後端服務。

所有人員、單位、公司、帳號與密碼均為虛構。請勿輸入真實個資或密碼。資料只寫入目前瀏覽器的 localStorage，可用左下「重設展示資料」恢復初始案例；不同瀏覽器的操作不會互相影響。切換展示角色是流程模擬，不是真正的登入或安全邊界。沒有真實寄信或建立帳號。

## 展示路徑

1. 進站直接開啟「帳號申請」→ 選系統及角色 → 送出，使用複製按鈕保存編號；「我的申請」查看紀錄及補件提醒。
2. 申請進度查詢使用完整編號與 DEMO 開頭的展示員工編號；第三人編號無法查詢。
3. 「管理者登入」選虛構角色，或右上角切換管理人甲／乙 → 申請案件處理 → 儲存處理中、退回補件或完成。展示入口不收集真實帳密。
4. 在查詢頁「帶入退回補件示例」→ 補件，修改權限使用人部門，觀察未完成任務重新指派、完成快照保留。
5. 已完成任務可開啟通知單，按「列印／存為 PDF」。只顯示當前管理人負責的任務與完成當時的資料。
6. 切換展示最高管理人 → 系統設定中心 → 停用系統、調整預設管理人或財務部門指派規則。

## 本次原檔參考

介面以 v19 舊版為主微調：灰白底色、粉紅操作按鈕、藍色章節標記，以及申請人→權限使用人→類型→系統→條件帳套→其他說明的欄位順序。依使用者明確要求保留原檔海霸王 Logo，桌機、手機、通知單與驗收表均可見；人員、案件及帳密仍為假資料。沒有發布原始程式、建築照片、預設登入密碼或附件。

功能以 regenerated 為基準，保留管理人分工、最高管理人設定權限，以及補件修改未完成角色。系統設定中心七個分類已補齊：系統、管理人、指派規則、角色、單位、帳套、申請歷程；支援主檔新增／修改／停用、條件優先序與編號萬用字元搜尋。歷史案件與已完成快照不隨主檔改名或停用變動。

兩份來源都使用條件規則直接指派系統管理人，沒有逐層主管核准流程。本展示尚未實作逐層簽核，也沒有宣稱正式服務已上線。展示管理人密碼僅驗證格式，不儲存密碼，不用於真實登入；真實寄信、多人資料同步與正式資料庫不在靜態展示範圍。

驗收入口：[測試驗收表](./acceptance.html)。包含 16 項操作與預期結果，可勾選並列印保存；填寫結果沒有自動儲存或送出。

手機採單欄表單與案件卡片；輸入字級 16px、手機送出按鈕至少 50px。保留既有瀏覽器假資料；如需恢復最新範例，可按「重設展示資料」。

## GitHub Pages

網站檔案位於 demo/；`.github/workflows/pages.yml` 只上傳此目錄，沒有後端程式、原始附件、資料庫、金鑰或連線設定。Actions 使用固定 commit 的官方 Pages actions，推送 main 的 demo 檔案變更後自動發布。

首次啟用需儲存庫管理人在 Settings → Pages → Build and deployment 選擇 GitHub Actions，再於 Actions 重跑發布工作；已啟用時會自動發布。此流程不要求額外管理權杖。私人儲存庫是否可使用 Pages 取決於 GitHub 方案；不要為此直接把含其他內容的儲存庫改為公開。
